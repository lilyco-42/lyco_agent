# CLI 路由器泛化实验记录（2026-09-19）

对象：端侧「意图 → CLI 命令」路由器，基座 `Qwen/Qwen3-0.6B`，数据/训练都在 CloudStudio A10 内核内完成。

## 1. 起因：原评测数字不可信

`tools/cli_datagen.py` 声称「泛化优先 / held-out」，但实际有**两处泄漏**，导致 `eval.jsonl` 与 `train.jsonl` 同分布：

1. **模板泄漏**：`t = R.choice(T[cap])` 从**全部**模板随机抽取，使 `HELD_OUT_PHRASES`
   （`turn on the {obj}` / `blink the {obj} {n} times` / `temperature` / `fan speed {v}` / `board info`）
   照样进入训练集。
2. **值域泄漏**：`elif cap == "led_blink"` 是**死代码**（`cap.startswith("led")` 先命中），
   于是 train 的 blink 次数取 `randint(1,15)`，把它声明要隔离的 held-out 值域 8–12 也覆盖了。

结果：训练 loss 在 epoch 0.3 降到 0.0002、之后恒为 0.0，`EVAL 命令精确匹配 270/270 = 100%`。
**这个 100% 是同分布指标，不能作为泛化依据。**

## 2. 本次评测方法（可复现）

- **heldA（未见说法）**：训练模板族与评估模板族**互斥**，评估只用训练中从未出现的说法。
- **heldB（弱线索困难集）**：刻意不出现「温度 / 内存 / 磁盘 / cpu / gpio / 风扇」等关键词，
  如「板子烫不烫」→ `hw temp`、「还剩多少地方存东西」→ `hw disk`，逼模型学**语义**而非关键词匹配。
- **数值值域真隔离**：fan 250–255、blink 8–12、gpio line 301–380 只出现在评估集。
- **泄漏断言**：训练脚本内 `leak == 0` 硬校验，不通过即视为无效实验。
- **同 run 对照**：v1 + 新版本在同一进程、同一评测集上测，避免跨 run 环境漂移。

## 3. 结果

| 模型 | 数据 | heldA 未见说法 | heldB 弱线索 | 拒绝率 |
|---|---|---|---|---|
| v1 | 原生成器 2580 条（同分布评测） | 89.2% / 89.4% | 81.5% / 78.8% | 71.4%（5/7） |
| v2 | v1 数据 + 6575 条 HF 英文 shell（混训） | 61.7% | — | **20.0%（1/7）** |
| v3 | 纯中文，说法族扩充，含硬负例 | **93.7%** | 77.3% | **100%（7/7）** |
| v4 | v3 + 无槽位能力说法倍增 + 拒绝类降比 | 90.0% | **80.3%** | **100%（7/7）** |

拒绝率定义：与硬件无关的请求应输出 `(无需调用硬件命令)`，输出其它命令即判失败。

## 4. 关键结论

1. **v1 并非「零泛化」**：它在未见说法集上仍有 ~89%。原先只凭「loss 归零」断定零泛化是**过度推断**；
   正确的说法是「原评测集不可作指标」，而非「模型没学到映射」。
2. **多任务混训，比例失衡比不混更糟**：英文 shell 占 v2 训练集 80%，直接冲淡中文硬件任务，
   并把拒绝行为从 100% 摧毁到 **20%** —— 模型被教会「什么都吐一条命令」。域不同时辅助数据必须 **≤10–15%**。
3. **硬负例是修拒绝率的有效手段**：加入「把屏幕亮度调高」「帮我连上 wifi」「给摄像头调焦距」
   等*看着像硬件但本 CLI 不支持*的请求后，拒绝率稳定回到 **100%**（v3/v4 一致复现）。
4. **⚠️ 评测噪声 ±3pp**：v1 在两轮里被独立评测，heldA 差 0.2pp，但 heldB 差 **2.7pp**。
   因此「v3 heldA +4.5pp」「heldB −4.2pp」这类单次差异**不构成显著改进**。
   要下结论必须：加大评测集 / 多种子重复 / 固定解码后多次取平均。
5. **命令准确率没有实质突破**：三版在 heldB 都是 78–81%、heldA 89–94%，**继续加数据已边际递减**。
   0.6B + 合成改写数据的语义天花板约在 80%（heldB）。
6. 因此**采用 v4**：拒绝率 100%（稳健收益）且准确率与 v1 持平 —— 对路由器而言
   「该不该调」比 3pp 准确率更重要。

## 5. 若要真正突破，需换杠杆

- **扩基座**：Qwen3-1.7B / Qwen2.5-1.5B（代价：端侧体积 ~600MB → ~1GB+）；
- **换数据源**：真实中文指令数据，而非合成改写（合成改写受限于单一作者的用词习惯）；
- **补充**：`cloudstudio/a10_hf_pull.py` 已能从 HF 拉取真实 NL→命令数据
  （`emirkaanozdemr/bash_command_data_6K`、`Eng-Elias/multios-terminal-commands`），
  但**只应作为小比例辅助**，见结论 2。

## 6. 工程经验（避免重踩）

- **去重后要看「每个能力还剩多少唯一样本」**，总数够不代表覆盖够。
  无数值槽位的能力（temp/cpu/mem/disk/info/fan_status）模板只有 9–14 条，
  按整句去重后每种能力只剩十几条唯一样本（v3 训练集 3944 条而非预期的 ~1 万）。
- **做说法倍增时，后缀/语气词必须同时加到负例（拒绝类）上**，
  否则模型会学到「带语气词 = 要出命令」的伪相关。
- **日志必须关 tqdm**（`disable_tqdm=True` + `TRANSFORMERS_VERBOSITY=error`），
  否则 132KB 进度条会把 traceback 冲掉，导致按上下文行误判错误原因。
- **读 traceback 要读 `File line N, in <fn>` 指向的最后一帧**，不要拿上下文行猜。
  本次曾据此误判为 `from_pretrained` 参数问题，实际是数据形态不一致
  （`gen_pair` 返回 `{"messages":[...]}`，HF 侧已剥成 list，`msgs[0]` 对 dict 取下标 → `KeyError: 0`）。

## 7. 模型合并：零成本的大幅提升（2026-09-19 追加）

依据：DeepSeek-V4.1-Flash 技术报告 §5.1.2 ——
> we use **model merging to reinitialize successive RL runs** ... combining improvements acquired along different
> optimization paths ... a simple and practical way to aggregate parallel RL compute.

**实测**（同一 run、同一评测集，独立复现两次结果完全一致）：

| 模型 | heldA（未见说法） | heldB（弱线索） | 拒绝率 |
|---|---|---|---|
| v4 | 91.7% (477/520) | 74.8% (247/330) | 100% |
| **v3 ⊕ v4（权重平均 0.5/0.5）** | **98.5%** (512/520) | **79.7%** (263/330) | 100% |

- **+6.8pp / +4.9pp，双双超出 ±3pp 噪声带**；两次独立评测给出**完全相同的命中数**（512/520、263/330）。
- **零训练成本**：只是把两条不同优化路径的 checkpoint 逐张量平均。
  合并后**同时优于 v3 和 v4 各自**（v3 强于 heldA、v4 强于 heldB）—— 正是报告所说"把不同优化路径的改进叠加"。

### 实现要点（内存安全）
用 `safetensors.safe_open` **惰性逐张量**读取后平均。
⚠️ 不要直接 `state_dict()` 两份再合并：会同时驻留两份 float32（每个 ~2.4GB）+ 结果 dict（再 ~2.4GB），
**曾把 CloudStudio 工作空间直接打崩**（状态变 `Error`，只能人工重启）。惰性版峰值只有 1~2 个张量。

### 本轮踩坑（写代码时请先对照仓库既有注释）
1. **`make_cmd` 用了 dict 字面量**按 cap 返回不同表达式 → dict 中**所有值都会被立即求值**，
   于是 `cap="temp"`（无槽位）时也会去算 `kw['v']` → `KeyError: 'v'`。
   `tools/cli_datagen.py` 第 64 行**已明文警告过这条**，仍被踩。→ **必须用 if/elif 惰性分支**。
2. `trl.GRPOTrainer(train_dataset=...)` 要求 `datasets.Dataset`，**传 list 会 TypeError**（需 `Dataset.from_list`）。
3. 变量批量改名后要全局 grep：`V5`→`V6` 漏了 `GRPOConfig(output_dir=V5)` → `NameError`。
