# 十年设计（2026 → 2036）：只押不会变的东西

> 起点：*"计算机消失，意图常驻"* —— 把「人怎么用软件」和「agent 干过的活」变成
> 可回放、可验证、内容寻址的**记忆资产**；能力从"拥有模型"转到"**拥有语料与验证**"。

## 一、先问：十年后什么必然还在？

任何押在"会变的东西"上的设计都会死。过去十年里变掉的东西：框架、模型、API、云厂商、
推理引擎、GPU 代次。**没变的只有三样**：

| 不变量 | 年龄 | 为什么十年后还在 |
|---|---|---|
| **进程边界（CLI）** | ~55 年 | POSIX/管道/退出码，从 1970 到 2026 一字未改；今天所有 AI 工具最终都在 `exec()` |
| **文件 + 内容寻址** | ~50 年 | 文件系统 + hash 寻址；不依赖任何厂商、可离线、可镜像 |
| **纯文本协议** | ~50 年 | 文本可 diff / 可 git / 可审计 / 人可读可手改，不需要工具链 |

**所以能力 = CLI；记忆 = 文件（mpkg）；协议 = 文本（ndjson / schema）。**
其余（模型、硬件、云、UI）全部视为**可替换零件**。

## 二、三条设计公理（从今天的实证里长出来的）

1. **确定性 > 智能**
   AI 是概率的，资产必须是确定的。所以：agent 可以乱想，但**产出的每一步都必须可回放**
   （trace 自包含、mpkg 内容寻址）。今天 `trace2mpkg → cache-node verify` 已跑通这条。

2. **可验证 > 可生成**
   实证教训（Radxa 蓝灯）：**"命令成功 + 软件回读成功" ≠ 物理世界生效**。
   所以 `verify` 的判定标准是**对真实世界**（退出码 / 目标机回读 / 外部观察），
   而不是"我觉得执行成功了"。假的 attestation 会摧毁整套信任机制。

3. **可降级 > 全自动**
   模型挂了、网断了、云没了，**手写一条 CLI 依然能干活**。这是 CLI 优先的保险丝。
   永远不允许"只有 AI 能驱动"的关键路径。

## 三、分层（十年不过时的四层）

```
① 意图层     自然语言 / 语音 / 视觉信号          ← 会换（模型代次）
② 契约层     --schema（自描述 CLI）              ← 十年锚点，向后兼容承诺
③ 动作层     CLI 进程（能力本体）                 ← 十年锚点，POSIX
④ 资产层     trace / mpkg / attestation          ← 十年锚点，内容寻址可离线
              （底层: 硬件/NPU/OS —— 随便换）
```

**关键：层与层之间只有文本契约。** 今天 Radxa 的 `hw`、明天的任何板子，
只要给出 `--schema` 就能被接入；今天的 0.6B 路由器、十年后的任何模型，
只要输出"一条命令文本"就能当②→③的翻译器。

## 四、写给十年的六个硬约束

1. **每个 CLI 必须自描述**：`<cli> --schema` 返回 JSON（参数/副作用/幂等性）。
   没有 schema 的能力不进注册表 —— 十年后的人靠它自动发现能力。
2. **每个能力必须可干跑**：`--dry-run` 输出"将要做什么"。不可逆操作先模拟。
3. **每条 mpkg 必须内容寻址 + 可离线回放**：不依赖任何中心服务；
   注册表只是索引，不是真理来源（可镜像、可 p2p、可 U 盘传）。
4. **每个 attestation 必须绑定环境**（硬件型号/OS/版本）+ **可复现脚本**。
   "某台机器上跑过"不等于"到处能跑"。
5. **trace 是审计日志**：谁在何时让哪个能力对哪个目标做了什么 —— 十年后合规、事故复盘、
   责任界定都靠它（今天 `lycore --trace` 已是雏形）。
6. **契约只增不改**：`--schema` 的字段只允许新增/弃用，不允许语义变更。
   破坏性变更必须发新版 CLI 名（`hw2`），旧版永久可用。

## 五、时间线（每阶段的可验证产出）

| 阶段 | 目标 | 可验证产出 |
|---|---|---|
| **0–1 年（现在）** | CLI 化 + 语料 + 验证链路 | `hw` 套件 · 路由器 98%/83% · trace→mpkg→verify 全通 |
| 1–3 年 | **语料与验证的护城河** | 数百个真实能力包 · attestation 从 0 起步并复利 · 注册表可离线镜像 |
| 3–5 年 | **分发网络** | 零边际成本分发；Radxa/NPU 网格当执行底盘；伙伴网（cute_box/lly）共用契约 |
| 5–10 年 | **意图层成为 OS 之上的一层** | 模型可随意替换；硬件随意替换；**能力资产沉淀成不可迁移的护城河** |

## 六、十年内必然发生的三件事，及我们的对策

| 必然发生 | 对我们意味着 | 对策（已内建） |
|---|---|---|
| **模型能力暴涨**，"路由器"角色被吞 | 模型层价值归零 | 我们从不押模型 —— 押 CLI 契约与验证资产；模型强了我们更省事 |
| **平台闭源化 / API 变更 / 断供** | 依赖云的设计全死 | 内容寻址 + 本地优先 + 可镜像（mpkg 天然具备） |
| **硬件碎片化**（NPU/新架构/多形态） | 适配成本爆炸 | CLI 化把适配收敛到"写一个 `--schema` 的脚本"（今天 `hw` 就是范例） |

## 七、一句话

> **十年里会变的都是零件，不会变的是"进程 + 文件 + 文本"。**
> 我们的设计就是把这些不变量做成契约，把每次干过的活沉淀成资产 ——
> 于是模型、硬件、云怎么换代，**我们的资产只会越攒越厚，不会作废**。
