# 实验：只改「配方」能否修 v1 的过拟合？（held-out 对照，2026-09-16）

> 触发：用户提出「过拟合了吧，是参数样本多样性太少质量不够」→ 按 `lyco` 信条 5
> **「横向对比必须控住变量」「只测一个配置就下结论 = 假阴性」** 设计本实验。
> 平台：CloudStudio A10（spaceKey `b0d0f5fb…`）。脚本：`tools/fc_train_v3.py`。

## 一、实验设计（控变量清单）

| 变量 | 是否控住 | 取值 |
|---|---|---|
| 底座模型 | ✅ 统一 | Qwen/Qwen3-0.6B（三个被评对象同源或同底） |
| 评测集 | ✅ 统一 held-out | 16 例 = 8 个「训练未见问法」的工具请求 + 8 个负样本 |
| 精度 | ✅ 统一 | 评测全部 bf16（未量化，避免量化档差异） |
| 评测方式 | ✅ 统一 | `do_sample=False`, max_new_tokens=256, `enable_thinking=False` |
| **本轮唯一改动** | — | **训练配方**（冷启动 SFT + loss masking + 负样本再平衡 + GRPO） |
| 数据来源 | ✅ 未变 | 仍是我们自己的语料（**未引入 HF 数据** → 留给 run B 单独验证） |
| 模型规模 | ✅ 未变 | 仍是 0.6B（不换 1.7B） |

**关键修正**：v1 的评测集与训练集**重叠** → 测的是记忆不是泛化。本轮改用 **held-out**（问法与训练不重叠）。

## 二、结果（同一套 held-out）

| 模型 | 工具选择准确率 | abstention（不误调） | **总体** |
|---|---|---|---|
| 基线 Qwen3-0.6B（未训） | 2/8 = 25% | 8/8 = **100%** | 10/16 = **62%** |
| **v1**（`qwen3_lyco_fc_corpus`，自称 "88%"） | 8/8 = 100% | 0/8 = **0%** | 8/16 = **50%** |
| **v3**（本轮） | 7/8 = **88%** | 8/8 = **100%** | 15/16 = **94%** |

## 三、结论

1. **用户的"过拟合"直觉被证实，且比预期严重**：v1 训练集内 88%，**held-out 仅 50%，低于不训练的基线 62%**。
   典型表现 = 过拟合到「**永远调工具**」（工具选择 100%、abstention 0%）。
2. **我上一轮的方法论错误被量化**：「88%」是**评测污染**的产物（train≈test）。修掉后 v1 现出原形。
3. **只改配方（不加数据、不换大模型）→ 94%**：+32 分 vs 基线，+44 分 vs v1。**两个指标同时达标**
   （工具选择 88% + abstention 100%），即**同时修好"该调"和"该不调"**。
4. **配方内容（逐条有依据）**：
   - **冷启动 SFT**（DeepSeek-R1 Nature 版：纯 RL「会做但不会好好表达」）；
   - **assistant-only loss masking**（只训 assistant token，抄 XYZ-Aquila 教程）；
   - **负样本再平衡**：训练 65 条 = 35 工具 + **30 负样本（46%）**（原 v1 仅 4/34 ≈ 12%）——Hammer 的 irrelevance 思想；
   - **GRPO 150 步**（在 SFT 之上）。
5. **对路线的含义**：**参数规模不是瓶颈，配方与评测口径才是**。这与 ToolGrad（数据质量>数量）、
   CacheRL（数据/奖励>复杂 RL）、Hammer（relevance 训练）一致。
