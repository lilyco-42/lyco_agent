## 一、口径错在哪（这是理解全部结论的前提）

### 1.1 废弃口径 vs 正确口径

| | ❌ 废弃：7 个固定工具 | ✅ 正确：brush 唯一出口 + 泛化 |
|---|---|---|
| 工具数 | 封闭枚举（7 个） | **开放世界（任意 CLI）** |
| 分母 | 7 | 任意 CLI |
| 新 CLI 出现 | **要重训 / 不可用** | **零成本可用**（不改模型、不重训） |
| 护城河 | 权重（训练覆盖） | **注入协议 + T1 门** |
| 能否撑 10 年 | ❌ 不能 | ✅ **可以** |

### 1.2 为什么 brush 口径天然「10 年可用」

**代码已是这个设计**（`_base06b_snapshot.py:212-226` 逐字）：

```python
def strip_brush(p):
    """剥掉 brush 前缀：brush docker ps -> docker ps（brush 是通用 shell，可执行任意 CLI）"""
    return p[len("brush "):] if p.startswith("brush ") else p
```

→ **`acc_exec`（剥 brush 前缀后判定）就是产品口径**，`acc`（严格匹配）只是研究指标。
**我们一直在用错误的口径读自己的成绩。**

## 三、泛用性的定量证据（这才是「10 年可用」的答案）

### 3.1 对照实验：训练时见过同名 CLI vs 没见过

评测集自带天然对照（`_p2_zs_A0.py` 的 `tier` 分级 + bash 回放污染计数）：

| 组 | CLI | 污染计数 | rag | scope_fs | plain |
|---|---|---|---|---|---|
| **跨域迁移**（brush 见过同名） | docker / npm | 29 / 35 | **50.0%** | 37.5% | 16.7% |
| **近零样本**（几乎没见过） | kubectl / terraform / yt-dlp | 7 / 4 / 2 | **36.1%** | 38.9% | 8.3% |

**⇒ 关键结论：两组差距仅 ~12pp（rag 口径）。**
**训练完全没见过的 CLI，靠 schema 注入就能到 36-39%。**

→ **「零训练接入新 CLI」成立。** 这不是理论，是实测。

### 3.2 注入协议是泛用性的载体（直接证据）

| 模式 | 含义 | 跨域 acc_exec 均值 |
|---|---|---|
| **rag** | schema 注入（告诉模型有哪些命令） | **58.3%** |
| scope_fs | 作用域 + few-shot | 46.7% |
| **plain** | 无注入，纯权重知识 | **20.0%** |

**⇒ 注入带来 2.9 倍提升（20.0% → 58.3%）。**
**而注入不需要重训** → 新 CLI 只需写一份 schema 块，**零成本接入**。

**这正是「未来 10 年依旧可用」的机制**：新工具出现时，
不改权重、不重训、不加代码 —— **只加一段注入文本**。

## 四、唯一真问题：出域拒绝（T1 门）

### 4.1 数据

| CLI | reject 组（4 条该拒） | acc |
|---|---|---|
| docker / kubectl / terraform / npm | 4 条 | **0.0%** |
| yt-dlp | 4 条 | **75.0%** |

**四个域拒绝率全 0%，只有 yt-dlp 是 75%。**

### 4.2 yt-dlp 为什么特殊（已定位）

1. **它是唯一 `tier=clean(2)`**（训练几乎没见过）
2. **它的 12 条 in-schema 全是 URL 槽位** → 模型没见过这种形态，倾向判为「不相关」
3. 它的失败是**误拒**：`pred = (无需调用硬件命令)` —— 该做的没做

**⇒ yt-dlp 的 0% 和 reject 的 75% 是同一个原因：语义上被判为「不属于已知域」。**

### 4.3 这为什么是唯一真问题

在 brush 口径下，「选错 CLI」不再是主要失败模式（因为 brush 出口通吃）。
剩下的两类真实错误：

| 失败模式 | 后果 | 谁来兜 |
|---|---|---|
| **误拒**（该做没做） | 用户问了下视频，得到「无需调用」 | ⚠️ **无兜底** |
| **危险放行**（该拒没拒） | docker/kubectl 的写操作被放过 | 🔴 **T1 门是唯一防线** |

⇒ **拒绝能力从来不在模型权重里**（base 臂同样 0%），
**必须在执行层用 T1 门兜** —— 这已是第 6 次一致证据。

## 五、修正后的判定

### 5.1 需求重新表述（建议）

> ~~在 7 个固定工具上达 90%~~
> **在 brush 通用出口下，对任意 CLI（含未训练过的）能给出可执行的正确命令；
> 危险/越权请求由 T1 门拦截；全程不依赖重训。**

### 5.2 逐条判定（brush 口径）

| 维度 | 现状 | 判定 |
|---|---|---|
| **泛用性**（未见 CLI 可用） | 近零样本组 **36-39%**（rag/scope_fs），vs 见过组 50% → **差距仅 ~12pp** | ✅ **机制成立** |
| **零成本扩展** | 注入协议 20.0% → 58.3%（**2.9×**），无需重训 | ✅ **成立** |
| 跨域整体产品能力 | A0 rag **58.3%** | ⚠️ 中等，但远高于此前认知的 11.7% |
| **出域误拒** | yt-dlp 类 0% | ❌ **待解** |
| **危险拦截** | 4 域拒绝 0% | 🔴 **必须靠 T1 门**（模型中无此能力） |
| PC GGUF | 已产出，端到端 9/9 | ✅ |
| 手机 .pte | 未做 | ❌ |
| 全流程可复现 | 管线齐全 | ✅ |

### 5.3 一句话结论

> **泛用性这条路是通的**——实测证明「没见过的 CLI 靠注入就能用」（36-39% vs 见到 50%），
> 且**不需要重训**（这正是 10 年可用的保证）。
> **真实产品能力被严格口径低估了 46.6pp**（11.7% → 58.3%）。
> **唯一真缺口是「误拒 + 危险放行」，而这本来就该由 T1 门而非模型承担。**
